Feature 2

Actionable Recommendations

Turn analysis into action. After scoring, show specific tips for each asset based on its risk level and chosen strategy.

Inspired by: digital-defense.io (300+ tips), GCA Toolkit, Security in a Box

Email Accounts — High Priority, Strategy: Fix

→ Enable 2FA on all email accounts

→ Use a password manager (Bitwarden, KeePass)

→ Check haveibeenpwned.com for breaches

→ Review connected third-party apps

Social Media — Medium Priority, Strategy: Replace

→ Migrate to privacy-respecting alternatives (Mastodon, Signal)

→ Audit privacy settings on current platforms

→ Remove unnecessary personal information

Feature 4

Accept Risk — 4th Strategy

Some risks aren't worth acting on. Let users consciously accept them with a justification note.

Inspired by: ThalesGroup ISRA (ISO 27005: Mitigate / Retain / Avoid / Share)

Fix Replace Remove Accept

Example: Old forum account

Strategy: Accept Risk

"Low-value account with no sensitive data. Not worth the effort to track down and delete."

Feature 5

Education Sidebar

Teach while assessing. Map EFF's 6 foundational questions to each step of the workflow.

Inspired by: EFF Surveillance Self-Defense, Security in a Box

Step A — Identify Assets

What do you want to protect?

"Your data, communications, and devices are your digital assets. Making a list is the first step to understanding what's at stake."

Step B — Threat Actors

Who are you protecting it from?

"Different adversaries have different capabilities. A pickpocket is not the same as a state actor."

Step C — Risk Rating

How bad are the consequences?

"Consider financial loss, reputational damage, physical safety, and emotional impact."

Step D — Vulnerability

How likely is the threat?

"A threat that's theoretically possible but extremely unlikely needs less attention than one that's already happening."

Staying Focused

What we're NOT building

Features we considered and deliberately rejected to keep Pattaya simple and private.

AI-generated threats

Requires external API calls. Breaks zero-dependency and privacy-first principles. (AWS Threat Composer uses Bedrock.)

Attack path AND/OR logic

Too complex for personal use. Enterprise pattern from ISRA that would overwhelm non-technical users.

Account system

No sign-ups, no servers. LocalStorage is the right call. (JSAT requires email.)

Backend API

Pattaya is client-only. No server to host, no data to leak, no infrastructure to maintain.
